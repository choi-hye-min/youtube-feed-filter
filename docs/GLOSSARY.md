# YouTube Feed Filter 용어집

이 문서는 프로젝트 기능을 설명하거나 수정할 때 사용자와 AGENT가 같은 의미로
용어를 사용할 수 있도록 정리한 기준 문서입니다. 사용자 관점의 설명과 실제 코드
관점의 의미가 다른 경우에는 두 관점을 함께 적습니다.

## 핵심 기능 용어

| 용어 | 사용자 관점 | AGENT 및 구현 관점 |
| --- | --- | --- |
| 필터(Filter) | 설정한 시간 기준보다 오래된 추천 영상을 자동으로 관심없음 처리하는 기능 | 현재 페이지에 맞는 어댑터를 활성화하고 후보 탐색, 업로드 시점 판정, 처리 큐 실행을 수행하는 전체 기능 |
| 시간 기준(Threshold) | 이 기간 이상 오래된 영상을 처리하도록 정하는 값 | `filter_threshold`에 저장되는 프리셋 키입니다. 예: `1day`, `1week`, `1month` |
| 기준 초과 | 영상의 업로드 시점이 선택한 시간 기준과 같거나 더 오래된 상태 | 파싱한 영상 나이(`age.ms`)가 기준 밀리초 값보다 크거나 같은 상태 (`age.ms >= thresholdMs`) |
| 관심없음(Not interested) | YouTube 추천에서 해당 영상을 제외하도록 보내는 사용자 피드백 | YouTube 데이터의 feedback 명령을 실행하거나 메뉴의 관심없음 항목을 클릭해 `v1/feedback` 처리를 유도하는 작업 |
| 추천 영상 카드(Card) | 홈 피드 또는 시청 페이지 추천 목록에 표시되는 영상 한 개 | 페이지 어댑터가 DOM에서 찾아 정규화하고 처리하는 후보 요소 |
| 플레이스홀더(Placeholder) | 관심없음 처리된 카드 자리에 표시되는 제목과 처리 사유 영역 | 홈에서는 확장 프로그램 소유 슬롯에 `.youtube-skip-placeholder`를 겹쳐 표시하고, Watch에서는 성공이 확인된 카드의 자식 요소를 교체한 결과 |
| 처리 사유 | 카드가 왜 관심없음 처리되었는지 보여주는 설명 | 영상의 업로드 시점 문자열과 현재 시간 기준 라벨을 조합한 플레이스홀더 문구 |
| 전역 필터 스위치 | 모든 페이지의 필터를 한 번에 켜거나 끄는 설정 | `filter_enabled` 상태입니다. 꺼지면 페이지별 설정보다 우선하며 현재 런타임과 대기 큐가 중단됩니다. |
| 페이지별 필터 | 홈 또는 시청 페이지에서만 필터를 개별적으로 켜거나 끄는 설정 | `home_filter_enabled`, `watch_filter_enabled` 상태로 활성 어댑터 선택에 사용됩니다. |
| 디버그 로깅 | 문제 확인을 위해 브라우저 콘솔 로그를 표시하는 옵션 | `logging_enabled`가 `true`일 때 페이지 런타임의 진단 로그를 출력하는 기능 |

## 페이지와 구성 요소

| 용어 | 의미 | 주요 코드 |
| --- | --- | --- |
| 홈 페이지(Home) | YouTube 메인 피드 경로인 `/` | `content-home.js` |
| 시청 페이지(Watch) | 영상 재생 경로인 `/watch`와 우측 추천 목록 | `content-watch.js` |
| 페이지 어댑터(Adapter) | 페이지별 DOM 구조 차이를 감싸는 탐색 및 판정 규칙 모음 | `window.YouTubeSkipHome`, `window.YouTubeSkipWatch` |
| 공유 런타임(Runtime) | 어댑터를 사용해 후보 탐색부터 큐 처리까지 실행하는 공통 엔진 | `content-shared.js`의 `createRuntime()` |
| 콘텐츠 스크립트(Content script) | YouTube 탭에서 상태를 읽고 현재 경로에 맞는 런타임을 시작하거나 중지하는 확장 프로그램 코드 | `content-script.js` |
| 메인 월드 스크립트(Main-world script) | YouTube 페이지 자체의 데이터와 명령 실행기에 접근하는 주입 스크립트 | `inject.js` |
| 백그라운드 서비스 워커 | 설정 저장, 메시지 처리, 탭 알림, 배지 갱신을 담당하는 확장 프로그램 구성 요소 | `background.js` |
| 팝업(Popup) | 확장 프로그램 아이콘을 눌렀을 때 표시되는 설정 및 통계 화면 | `popup.html`, `popup.js`, `styles.css` |
| SPA 탐색 | 전체 페이지 새로고침 없이 YouTube 내부 경로가 바뀌는 이동 방식 | `yt-navigate-finish`와 `popstate` 이벤트를 통해 활성 페이지를 다시 판정합니다. |

## 탐색과 판정 용어

| 용어 | 의미 |
| --- | --- |
| 후보(Candidate) | 어댑터의 DOM 선택자에 일치하여 검사 대상이 된 요소 |
| 정규화(Normalize) | 내부 요소로 발견된 후보를 실제 카드 단위 요소로 맞추는 과정 |
| 적격성(Eligible) | 후보가 현재 페이지의 올바른 추천 영역에 속하는지 확인하는 조건 |
| 영상 ID(Video ID) | `/watch?v=` 링크에서 추출한 YouTube 영상 식별자. DOM이 교체되어도 같은 영상을 다시 찾는 데 사용합니다. |
| 업로드 시점(Age) | `3 days ago`, `2주 전`처럼 카드에 표시된 상대 시간 정보 |
| 업로드 시점 파싱 | 영어 또는 한국어 상대 시간 문자열을 밀리초 값과 원문으로 변환하는 과정 |
| DOM 재사용 | YouTube가 스크롤이나 목록 갱신 중 기존 카드 요소를 다른 영상에 다시 사용하는 동작 |
| 재탐색(Reacquire) | 큐 처리 직전에 영상 ID로 현재 DOM의 최신 카드 요소를 다시 찾는 과정 |
| MutationObserver | 추천 카드가 동적으로 추가되거나 교체되는 것을 감지해 필터를 다시 적용하는 브라우저 API |

## 처리 상태와 통계

### 카드 처리 상태

카드 상태는 `data-youtube-skip-{page}-processed` 속성에 기록됩니다.

| 상태 | 의미 |
| --- | --- |
| `detected` | 후보로 발견되어 검사를 시작한 상태 |
| `checked` | 업로드 시점을 확인했지만 시간 기준보다 최신이라 처리하지 않은 상태 |
| `queued` | 기준을 초과해 관심없음 처리 큐에 들어간 상태 |
| `done` | 관심없음 작업 성공이 확인된 상태 |
| `failed` | 재시도 후에도 관심없음 작업이 성공하지 못한 상태 |

### 통계

| 용어 | 정확한 의미 |
| --- | --- |
| Detected | 현재 탭의 런타임이 새 검사 대상으로 발견한 카드 수. 시간 기준을 초과한 영상 수만 의미하지는 않습니다. |
| Skipped | 관심없음 작업 성공이 확인되어 플레이스홀더로 반영된 영상 수 |
| 배지(Badge) | 확장 프로그램 아이콘에 표시되는 현재 탭의 Skipped 통계 |

통계는 영구 저장 값이 아니라 콘텐츠 스크립트 실행 중 메모리에 유지되는 값입니다.
페이지 런타임이 바뀌어도 같은 콘텐츠 스크립트 안에서는 누적될 수 있으며, 탭을 새로
불러오면 초기화됩니다.

## 관심없음 처리 용어

| 용어 | 의미 |
| --- | --- |
| API 방식 | 카드 데이터에서 관심없음 feedback 명령을 찾아 YouTube의 명령 실행기로 직접 전달하는 우선 처리 방식 |
| UI 방식 | API 방식이 불가능할 때 카드 메뉴를 열고 관심없음 항목을 실제 클릭하는 대체 처리 방식 |
| 성공 확인 | 주입 스크립트가 작업 결과를 콘텐츠 스크립트에 응답한 상태. 성공한 경우에만 Skipped와 플레이스홀더에 반영합니다. |
| 순차 처리 큐 | 여러 카드의 메뉴와 feedback 요청이 충돌하지 않도록 한 번에 하나씩 처리하는 대기열 |
| 재시도 | 처리 실패 또는 DOM 교체에 대응해 최신 카드 요소를 다시 찾고 최대 3회 작업하는 절차 |
| 처리 간격(Action delay) | 한 작업 후 YouTube가 추천 목록을 정리할 시간을 주기 위한 대기 시간 |
| 슬롯 예약(Placeholder slot) | 홈 또는 Watch 추천 카드가 처리 중 DOM에서 사라져도 목록 높이와 플레이스홀더 위치를 유지하기 위한 요소. 홈에서는 YouTube의 lazy-load DOM 정리 후에도 독립 슬롯을 원래 위치에 복구해 유지합니다. |

## 설정 저장 키

모든 설정은 `chrome.storage.local`에 저장됩니다.

| 저장 키 | 의미 | 기본값 |
| --- | --- | --- |
| `filter_threshold` | 선택한 시간 기준 프리셋 | `1month` |
| `filter_enabled` | 전역 필터 활성화 여부 | `true` |
| `home_filter_enabled` | 홈 페이지 필터 활성화 여부 | `true` |
| `watch_filter_enabled` | 시청 페이지 필터 활성화 여부 | `true` |
| `logging_enabled` | 디버그 로그 활성화 여부 | `false` |

## 전체 처리 흐름

1. 팝업에서 사용자가 필터 설정을 변경합니다.
2. 백그라운드 서비스 워커가 설정을 저장하고 열린 YouTube 탭에 재적용을 알립니다.
3. 콘텐츠 스크립트가 전역 및 페이지별 설정과 현재 경로를 확인합니다.
4. 현재 페이지에 맞는 어댑터와 공유 런타임이 활성화됩니다.
5. 런타임이 추천 카드 후보를 찾고 영상 ID, 제목, 업로드 시점을 읽습니다.
6. 업로드 시점이 시간 기준 이상이면 카드를 순차 처리 큐에 넣습니다.
7. 주입 스크립트가 API 방식을 먼저 시도하고, 실패하면 UI 방식을 시도합니다.
8. 성공 응답이 확인되면 Skipped와 배지를 갱신하고, 홈에서는 독립 슬롯에 플레이스홀더를 표시하며 Watch에서는 카드를 플레이스홀더로 바꿉니다.

## 용어 사용 원칙

- `필터링됨`은 기준 초과 판정만 뜻할 수 있으므로, 실제 YouTube feedback까지 완료된
  경우에는 `관심없음 처리 성공`이라고 표현합니다.
- `Detected`를 오래된 영상 수 또는 처리 대상 수로 설명하지 않습니다. 이는 검사한 새
  카드 수입니다.
- `Skipped`는 단순히 화면에서 숨긴 수가 아니라 성공 응답을 받은 수를 뜻합니다.
- `홈 피드`와 `Watch 추천 목록`은 DOM 구조와 어댑터가 다르므로 수정 범위를 구분합니다.
- `시간 기준 초과`에는 기준과 정확히 같은 나이도 포함됩니다.
- 코드 변경 시 페이지별 DOM 선택자는 해당 어댑터에, 공통 큐와 상태 로직은
  `content-shared.js`에 둡니다.
