# 확장 프로그램 릴리스 동기화

확장 프로그램 버전과 릴리스 변경 사항의 영향을 받는 문서만 업데이트한다.

## 작업 절차

1. `AGENTS.md`, `src/manifest.json`, `README.md`, `docs/` 바로 아래의 Markdown 파일을 읽는다.
2. 관련 없는 사용자 작업을 덮어쓰지 않도록 `git status`와 관련 diff를 확인하여 릴리스 변경 사항을 파악한다.
3. 현재 버전과 릴리스 diff를 바탕으로 대상 버전을 결정한다.
   - `src/manifest.json`에서 읽은 현재 버전을 사용자에게 명시한다.
   - 사용자가 정확한 버전을 지정하면 해당 버전을 사용한다.
   - 사용자가 `patch`, `minor`, `major` 중 하나를 요청하면 해당 시맨틱 버전 증가를 적용한다.
   - 대상 버전이 지정되지 않았으면 릴리스 diff에 필요한 가장 작은 증가를 추천한다.
     - 버그 수정, 문서 정정, 내부 안정화처럼 기존 기능과 호환되는 변경은 `patch`를 추천한다.
     - 기존 기능과 호환되는 새 기능이나 사용자 기능 확장은 `minor`를 추천한다.
     - 기존 동작, 설정, 저장 데이터 또는 메시지 계약과 호환되지 않는 변경은 `major`를 추천한다.
   - 현재 버전과 `patch`, `minor`, `major` 적용 결과를 계산하고 추천 이유를 한 문장으로 설명한다.
   - 선택형 사용자 입력 도구를 사용할 수 있으면 추천 버전을 첫 번째이자 권장 옵션으로 배치하고, 나머지 SemVer 후보를 함께 제시하여 사용자가 선택하게 한다.
   - 선택형 사용자 입력 도구를 사용할 수 없으면 같은 후보를 번호 목록으로 제시하고 선택을 요청한다.
   - 사용자가 선택하기 전에는 파일을 수정하지 않으며 대상 버전을 임의로 확정하지 않는다.
4. 대상 버전이 현재 버전보다 높고 음이 아닌 정수 세 부분으로 구성된 `MAJOR.MINOR.PATCH` 형식인지 확인한다.
5. `src/manifest.json`의 최상위 `version` 필드만 수정한다. 기존 파일 형식과 키 순서를 유지한다.
6. 릴리스 diff를 검토하고 변경된 동작 때문에 기존 설명이 불완전하거나 부정확해진 문서만 업데이트한다.
   - 사용자에게 보이는 동작, 설정, 권한, 사용법, 설치 방법 또는 메시지 계약이 변경되면 `README.md`를 업데이트한다.
   - 주제가 변경된 관련 `docs/*.md` 파일만 업데이트한다.
   - 저장소에서 이미 관리하고 있거나 사용자가 요청한 경우가 아니면 일반적인 릴리스 노트, 날짜 또는 버전 배지를 추가하지 않는다.
   - 관련 없는 Markdown 문구나 형식을 수정하지 않는다.
7. `README.md`와 `docs/*.md`에서 이전 버전과 릴리스에서 변경된 용어를 검색한다. 현재 확장 프로그램 버전이나 변경된 동작을 설명하는 참조만 교체하고 과거 기록은 보존한다.
8. 결과를 검증한다.
   - `src/manifest.json`을 JSON으로 파싱하고 `version`이 대상 버전과 같은지 확인한다.
   - `git diff -- src/manifest.json README.md docs`를 검토한다.
   - 변경된 모든 문서 줄이 릴리스 변경 사항과 직접 관련되는지 확인한다.
   - 저장소에 적용되는 검사를 실행한다. 해당 검사가 없으면 수행한 JSON 및 diff 검사를 보고한다.

## 제약 사항

- 변경 범위를 최소화한다. 사용자가 별도로 요청하지 않으면 확장 프로그램 소스 코드를 수정하지 않는다.
- 버전이 변경되었다는 이유만으로 모든 문서를 업데이트하지 않는다.
- 관련 없는 작업 트리 변경 사항을 보존하고 안전한 수정을 방해하는 충돌이 있으면 알린다.
- 동작, 설정, 권한 또는 메시지 계약이 변경되면 적절한 `README.md` 변경을 포함해야 한다는 저장소 요구 사항을 따른다.
- 이전 버전과 새 버전, 변경한 문서, 변경하지 않은 문서 및 검증 결과를 보고한다.
