# YouTube Feed Filter 용어집

이 문서는 프로젝트 기능을 설명하거나 수정할 때 사용자와 AGENT가 같은 의미로
용어를 사용할 수 있도록 정리한 기준 문서입니다. 사용자 관점의 설명과 실제 코드
관점의 의미가 다른 경우에는 두 관점을 함께 적습니다.

## 핵심 기능 용어

| 용어 | 사용자 관점 | AGENT 및 구현 관점 |
| --- | --- | --- |
| 필터(Filter) | 설정한 시간 기준보다 오래되거나 홈에서 누적 N회 노출된 추천 영상을 자동으로 관심없음 처리하는 기능 | 현재 페이지에 맞는 어댑터를 활성화하고 후보 탐색, 업로드 시점·반복 노출 판정, 처리 큐 실행을 수행하는 전체 기능 |
| 시간 기준(Threshold) | 이 기간 이상 오래된 영상을 처리하도록 정하는 값 | `filter_threshold`에 저장되는 프리셋 키입니다. 예: `1day`, `1week`, `1month` |
| 반복 노출 필터 | 홈 방문마다 실제 화면에 나타난 영상이 누적 N회에 도달하면 처리하는 기능 | `repeat_filter_enabled`로 켜며 기본 OFF입니다. 전체·홈 필터와 로그인 조건도 충족해야 합니다. 업로드 기간 조건과 OR로 결합하며 두 조건에 해당해도 한 번만 처리합니다. |
| 노출 기준 N | 사용자가 설정하는 누적 노출 횟수 | `repeat_exposure_threshold`에 저장하는 2 이상의 안전한 정수이며 기본값은 3입니다. 변경 시 현재 방문의 노출 기록으로 재평가하고 실행 직전 최신 기준을 확인합니다. |
| 기준 초과 | 영상의 업로드 시점이 선택한 시간 기준과 같거나 더 오래된 상태 | 파싱한 영상 나이(`age.ms`)가 기준 밀리초 값보다 크거나 같은 상태 (`age.ms >= thresholdMs`) |
| 관심없음(Not interested) | YouTube 추천에서 해당 영상을 제외하도록 보내는 사용자 피드백 | YouTube 데이터의 feedback 명령을 실행하거나 메뉴의 관심없음 항목을 클릭해 `v1/feedback` 처리를 유도하는 작업 |
| 추천 영상 카드(Card) | 홈 피드 또는 시청 페이지 추천 목록에 표시되는 영상 한 개 | 페이지 어댑터가 DOM에서 찾아 정규화하고 처리하는 후보 요소 |
| 숨김 결과 카드(Hidden result card) | 관심없음 처리 후 YouTube가 카드 자리에 표시하는 `동영상 숨김` 안내 영역 | YouTube DOM의 `.ytDismissibleItemReplacedContent` 요소이며, 확장 프로그램은 안내 문구를 처리 사유와 영상 제목으로 바꿉니다. |
| 숨김 사유 문구 | 어떤 영상이 어떤 기준으로 관심없음 처리되었는지 보여주는 안내 | `[N일전 업로드]` 또는 `[홈에서 누적 N회 노출]` 다음 줄에 제목을 표시합니다. 두 조건을 모두 만족하면 반복 노출 사유를 우선합니다. |
| 전역 필터 스위치 | 모든 페이지의 필터를 한 번에 켜거나 끄는 설정 | `filter_enabled` 상태입니다. 꺼지면 현재 런타임과 대기 작업을 취소하고 미완료 표식을 해제합니다. 이미 제출된 feedback을 되돌리지는 않습니다. |
| 페이지별 필터 | 홈 또는 시청 페이지에서만 필터를 개별적으로 켜거나 끄는 설정 | `home_filter_enabled`, `watch_filter_enabled` 상태로 활성 어댑터 선택에 사용됩니다. |
| 디버그 로깅 | 문제 확인을 위해 브라우저 콘솔 로그를 표시하는 옵션 | `logging_enabled`가 `true`일 때 예상 가능한 feedback 진단 로그를 출력하는 기능 |

## 페이지와 구성 요소

| 용어 | 의미 | 주요 코드 |
| --- | --- | --- |
| 홈 페이지(Home) | YouTube 메인 피드 경로인 `/` | `content-home.js` |
| 시청 페이지(Watch) | 영상 재생 경로인 `/watch`와 우측 추천 목록 | `content-watch.js` |
| 페이지 어댑터(Adapter) | 페이지별 DOM 구조 차이를 감싸는 탐색 및 판정 규칙 모음 | `window.YouTubeSkipHome`, `window.YouTubeSkipWatch` |
| 공유 런타임(Runtime) | 어댑터를 사용해 후보 탐색부터 큐 처리까지 실행하는 공통 엔진 | `content-shared.js`의 `createRuntime()` |
| 콘텐츠 스크립트(Content script) | YouTube 탭에서 상태를 읽고 현재 경로에 맞는 런타임을 시작하거나 중지하는 확장 프로그램 코드 | `content-script.js` |
| 메인 월드 스크립트(Main-world script) | YouTube 페이지 자체의 데이터와 명령 실행기에 접근하는 주입 스크립트 | `inject.js` |
| 백그라운드 서비스 워커 | 설정·누적 노출·방문별 중복 기록 저장, 메시지 처리, 탭 알림, 배지 갱신을 담당하는 확장 프로그램 구성 요소 | `background.js` |
| 팝업(Popup) | 확장 프로그램 아이콘을 눌렀을 때 표시되는 설정 및 통계 화면 | `popup.html`, `popup.js`, `styles.css` |
| SPA 탐색 | 전체 페이지 새로고침 없이 YouTube 내부 경로가 바뀌는 이동 방식 | `yt-navigate-finish`와 `popstate` 이벤트를 통해 활성 페이지를 다시 판정합니다. |

## 탐색과 판정 용어

| 용어 | 의미 |
| --- | --- |
| 후보(Candidate) | 어댑터의 DOM 선택자에 일치하여 검사 대상이 된 요소 |
| 정규화(Normalize) | 내부 요소로 발견된 후보를 실제 카드 단위 요소로 맞추는 과정 |
| 적격성(Eligible) | 후보가 현재 페이지의 올바른 추천 영역에 속하는지 확인하는 조건 |
| 영상 ID(Video ID) | `/watch?v=` 링크에서 추출한 YouTube 영상 식별자. DOM이 교체되어도 같은 영상을 다시 찾는 데 사용합니다. |
| 업로드 시점(Age) | `3 days ago`, `2주 전`처럼 카드에 표시된 상대 시간 정보 |
| 업로드 시점 파싱 | 영어 또는 한국어 상대 시간 문자열을 밀리초 값과 원문으로 변환하는 과정 |
| DOM 재사용 | YouTube가 스크롤이나 목록 갱신 중 기존 카드 요소를 다른 영상에 다시 사용하는 동작 |
| 재탐색(Reacquire) | 큐 처리 직전에 영상 ID로 현재 DOM의 최신 카드 요소를 다시 찾는 과정 |
| MutationObserver | 추천 카드가 동적으로 추가되거나 교체되는 것을 감지해 필터를 다시 적용하는 브라우저 API |
| 홈 방문(Home visit) | 최초 홈 진입·새로고침·홈 복귀·홈 피드 갱신 등으로 시작하는 한 번의 방문. 스크롤, DOM 교체, 탭 전환, 설정 변경은 같은 방문을 유지합니다. |
| 방문 식별자(Visit ID) | 콘텐츠 스크립트가 만드는 방문별 식별자. background는 탭 ID와 문서 ID를 함께 확인하고 `(visitId, videoId)` 중복 기록을 막습니다. |
| 실제 화면 노출 | 문서가 보이는 상태에서 홈 카드의 50% 이상이 화면에 들어온 경우. 스크롤로 들어온 카드도 포함하며, DOM에만 존재하거나 백그라운드 탭에 있는 카드는 제외합니다. |
| IntersectionObserver | 카드와 화면의 교차 비율을 감지하는 브라우저 API. 홈 어댑터에서 문서 표시 상태와 함께 실제 노출을 판정합니다. |
| 누적 노출 횟수 | 서로 다른 홈 방문에서 실제 노출된 횟수. 같은 Chrome 프로필의 탭이 공유하며 한 방문에서 같은 영상은 최대 1회 증가합니다. 중간 방문 미노출·날짜 경과·처리 성공/실패로 초기화하지 않습니다. |
| 방문 내 횟수 스냅샷 | 현재 방문에서 영상 노출을 저장한 뒤 background가 반환한 누적값. 현재 탭의 반복 판정에 사용하며, 다른 탭이 나중에 추가한 횟수는 기존 스냅샷에 실시간 반영하지 않습니다. |

## 처리 상태와 통계

### 카드 처리 상태

카드 상태는 `data-youtube-skip-{page}-processed` 속성에 기록됩니다.

| 상태 | 의미 |
| --- | --- |
| `detected` | 후보로 발견되어 검사를 시작한 상태 |
| `checked` | 업로드 시점을 확인했지만 현재 조건에서 처리하지 않은 상태. 이후 실제 노출 기록이 반복 기준을 만족하면 다시 판정합니다. |
| `queued` | 기준을 초과해 관심없음 처리 큐에 들어간 상태 |
| `done` | 관심없음 작업 성공이 확인된 상태 |
| `failed` | 재시도 후에도 관심없음 작업이 성공하지 못한 상태 |

### 통계

| 용어 | 정확한 의미 |
| --- | --- |
| Detected | 현재 탭에서 새 검사 대상으로 발견한 카드 수. 같은 카드·영상 ID의 메타데이터 재검사와 설정 변경은 중복 집계하지 않습니다. 시간 기준을 초과한 영상 수만 의미하지는 않습니다. |
| Skipped | 관심없음 요청 후 대상 카드의 YouTube 숨김 결과가 확인된 영상 수. 서버 저장 완료를 보장하지는 않습니다. |
| 배지(Badge) | 확장 프로그램 아이콘에 표시되는 현재 탭의 Skipped 통계 |

Detected/Skipped 통계는 영구 저장 값이 아니라 콘텐츠 스크립트 실행 중 메모리에 유지되는 값입니다.
페이지 런타임이 바뀌어도 같은 콘텐츠 스크립트 안에서는 누적될 수 있으며, 탭을 새로
불러오면 초기화됩니다. 영상별 누적 노출 횟수는 이 통계와 별개이며 영구 저장합니다.

## 관심없음 처리 용어

| 용어 | 의미 |
| --- | --- |
| API 방식 | 카드 데이터에서 관심없음 feedback 명령을 찾아 YouTube의 명령 실행기로 직접 전달하는 우선 처리 방식 |
| UI 방식 | API 방식이 불가능할 때 카드 메뉴를 열고 관심없음 항목을 실제 클릭하는 대체 처리 방식. 홈 메뉴에 관심없음 항목이 없으면 즉시 닫고 같은 카드 재시도를 중단합니다. |
| 성공 확인 | 대상 카드 또는 동일 위치의 대체 카드에서 새로운 숨김 결과를 확인한 상태. 요청 ID로 결과를 표시하여 해당 결과에만 숨김 사유를 쓰고 Skipped를 증가시킵니다. |
| 순차 처리 큐 | 여러 카드의 메뉴와 feedback 요청이 충돌하지 않도록 한 번에 하나씩 처리하는 대기열 |
| 재시도 | 처리 실패 또는 DOM 교체에 대응해 최신 카드 요소를 다시 찾고 최대 3회 작업하는 절차 |
| 처리 간격(Action delay) | 한 작업 후 YouTube가 추천 목록을 정리할 시간을 주기 위한 대기 시간 |

## 설정 저장 키

모든 설정은 `chrome.storage.local`에 저장됩니다.

| 저장 키 | 의미 | 기본값 |
| --- | --- | --- |
| `filter_threshold` | 선택한 시간 기준 프리셋 | `1month` |
| `filter_enabled` | 전역 필터 활성화 여부 | `true` |
| `home_filter_enabled` | 홈 페이지 필터 활성화 여부 | `true` |
| `watch_filter_enabled` | 시청 페이지 필터 활성화 여부 | `true` |
| `repeat_filter_enabled` | 홈 반복 노출 필터 활성화 여부 | `false` |
| `repeat_exposure_threshold` | 누적 노출 횟수 기준 N | `3` |
| `logging_enabled` | 디버그 로그 활성화 여부 | `false` |

`home_exposure_history`에는 설정과 별도로 영상별 `counts`와 탭별 `visits`를 저장합니다.
각 방문은 방문 ID, 문서 ID, 이미 집계한 영상 ID 목록(`seen`)을 포함합니다. background가
변경을 직렬화하고 누적값과 방문 기록을 한 저장 키에 함께 기록하므로, 동시 탭의 증가분이
덮어써지거나 저장 후 응답 유실·재전송·워커 재시작으로 같은 노출이 다시 증가하지 않습니다.
중복 요청은 저장 없이 최신 공유 누적값을 반환합니다.

워커 재시작 시 두 기록을 복원합니다. 탭 종료는 해당 방문만, 브라우저 시작은 전체 방문
정보만 정리하며 영상별 누적값은 보존합니다. `getState`는 설정만 반환하고, 개별 영상의
횟수는 노출 기록 응답으로 받습니다. 날짜 기반 만료나 누적값 자동 삭제는 없습니다.

## 전체 처리 흐름

1. 팝업에서 사용자가 필터 설정을 변경합니다.
2. 백그라운드 서비스 워커가 설정을 저장하고 열린 YouTube 탭에 재적용을 알립니다.
3. 저장 설정·주입 스크립트 로드·로그인이 확인되면 전역 및 페이지별 설정과 현재 경로를 확인합니다.
4. 현재 페이지에 맞는 어댑터와 공유 런타임이 활성화됩니다.
5. 런타임이 추천 카드 후보를 찾고 영상 ID, 제목, 업로드 시점을 읽습니다.
6. 홈 반복 필터가 켜져 있으면 방문을 등록하고 실제 화면에 나타난 영상의 노출을 기록합니다. 저장이 확인된 누적값으로 반복 기준을 판정합니다.
7. 업로드 시점이 시간 기준 이상이거나 홈 누적 노출 횟수가 N 이상이면 카드를 순차 처리 큐에 한 번만 넣습니다. 업로드 시점을 읽지 못해도 반복 조건으로 처리할 수 있습니다.
8. 실행 직전 영상 ID와 최신 기준을 재검증합니다. 주입 스크립트가 명시적인 관심없음 명령과 실행기를 찾으면 API 방식을 사용하고, 찾지 못하면 UI 방식을 사용합니다.
9. 대상 카드의 숨김 결과가 확인되면 Skipped와 배지를 갱신하고, 해당 결과 문구를 업로드 시점 또는 누적 노출 사유와 영상 제목으로 바꿉니다. 노출 누적값은 유지합니다.

## 용어 사용 원칙

- `필터링됨`은 기준 초과 판정만 뜻할 수 있으므로, 실제 YouTube feedback까지 완료된
  경우에는 `관심없음 처리 성공`이라고 표현합니다.
- `Detected`를 오래된 영상 수 또는 처리 대상 수로 설명하지 않습니다. 이는 검사한 새
  카드 수입니다.
- `Skipped`는 단순히 화면에서 숨긴 수가 아니라 성공 응답을 받은 수를 뜻합니다.
- `홈 피드`와 `Watch 추천 목록`은 DOM 구조와 어댑터가 다르므로 수정 범위를 구분합니다.
- `시간 기준 초과`에는 기준과 정확히 같은 나이도 포함됩니다.
- `누적 노출`은 연속 방문을 뜻하지 않습니다. N=3일 때 1·2·4번째 방문에서 보였다면 3번째 방문의 미노출과 관계없이 4번째에 처리합니다.
- 반복 필터의 누적값과 `Detected`/`Skipped` 통계를 혼용하지 않습니다. `/watch`의 검사는 홈 노출 횟수를 증가시키지 않습니다.
- 코드 변경 시 페이지별 DOM 선택자는 해당 어댑터에, 공통 큐와 상태 로직은
  `content-shared.js`에 둡니다.
