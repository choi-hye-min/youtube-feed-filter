# 홈 피드 반복 노출 영상 자동 관심 없음 처리 작업 계획

- 작성일: 2026-10-31 (KST)
- 상태: 구현·자동 검사·로컬 Chrome 검증 완료, 실제 YouTube 수동 검증 대기
- 목적: 서로 다른 홈 방문에서 실제 화면에 반복 노출된 영상을 사용자 설정 횟수에 따라 자동으로 관심 없음 처리한다.

## 1. 확정 요구사항

1. YouTube 홈(`/`) 피드의 영상별 **누적 노출 횟수**를 기록한다.
2. 처리 기준 `N`은 사용자가 팝업에서 설정할 수 있어야 한다.
3. 스크롤을 포함해 실제 화면에 보인 영상만 노출로 집계한다. DOM에 로드된 사실만으로 집계하지 않는다.
4. 같은 홈 방문에서는 같은 영상이 여러 번 보여도 최대 1회만 집계한다.
5. 중간 홈 방문에서 영상이 보이지 않아도 기존 누적 횟수를 유지한다.
6. 날짜 경과에 따른 초기화나 최근 7일 같은 집계 기간 제한을 두지 않는다.
7. 현재 방문의 노출을 반영한 누적 횟수가 `N` 이상이면 기존 관심 없음 처리 큐를 통해 실행한다.
8. 누적 횟수는 실제 노출 이력이다. 관심 없음 처리 성공·실패나 설정 변경을 이유로 초기화하지 않는다.

이 문서의 횟수는 연속 방문 횟수가 아니다. 직전 방문에 나타났는지 비교하거나, 미노출 방문에서 기록을 지우는 로직을 구현하지 않는다.

### 대표 시나리오

`N = 3`이고 기존 업로드 기간 필터에는 해당하지 않는 영상 A를 기준으로 한다.

| 홈 방문 | 실제 화면 노출 | 누적 횟수 | 기대 동작 |
| --- | --- | ---: | --- |
| 1번째 | 보임 | 1 | 기록 후 유지 |
| 2번째 | 보임 | 2 | 기록 후 유지 |
| 3번째 | 안 보임 | 2 | 기존 횟수 유지 |
| 4번째 | 보임 | 3 | 관심 없음 처리 |

같은 방문에서 다시 스크롤해 A를 보거나, A의 카드 DOM이 교체되어도 횟수는 추가로 증가하지 않는다.

## 2. 구현 정책

구현 착수 시 다음 기본안을 적용했다. 사용자 지정 N과 누적 유지 요구사항을 기준으로 동작한다.

| 항목 | 기본안 또는 결정 사항 |
| --- | --- |
| 반복 필터 설정 | 별도 ON/OFF 제공, 기본 OFF |
| N 입력 | 기본값 3, 2 이상의 안전한 정수. 빈 값·소수·문자열 오류 등 잘못된 입력은 저장하지 않음 |
| 실제 노출 판정 | 문서가 보이는 상태에서 카드의 50% 이상이 화면에 들어오면 집계. 별도 체류 시간 조건은 추가하지 않음 |
| 기존 필터와 결합 | 업로드 기간 조건 또는 반복 노출 조건을 만족하면 처리. 두 조건 모두 해당해도 같은 큐에서 한 번만 처리 |
| 기능 중단 | 전체·홈·반복 필터 OFF 또는 미로그인 상태에서는 반복 노출 기록과 해당 사유의 작업을 중단하고 기존 누적값은 보존 |
| N 변경 | 현재 방문에서 이미 노출된 카드를 즉시 재평가. 횟수는 증가시키지 않으며, N을 높이면 새 기준에 미달하는 반복 사유의 대기 작업을 취소 |
| 기록 유지 | 누적값은 `chrome.storage.local`에 저장해 페이지·서비스 워커·브라우저 재시작 후에도 보존 |
| 여러 탭의 합산 | 같은 Chrome 프로필의 누적값을 공유하고 탭별 방문·중복 기록을 분리한다. YouTube 계정별로는 분리하지 않는다. |

여러 탭의 기록은 프로필 공통 누적값에 반영하며 각 탭의 방문당 최대 1회로 집계한다. 탭 전환만으로 새 홈 방문을 만들지 않는다.

현재 공통 런타임은 DOM 변경, 스크롤, 3초 주기로 같은 카드를 재검사한다. `apply()` 호출 횟수와 `Detected` 통계를 노출 횟수로 사용하면 안 된다. 현재 카드 검사 또한 크기·연결 상태만 확인하므로 실제 화면 노출 감지가 별도로 필요하다.

또한 `apply()`의 `checked` 상태와 업로드 시점 파싱 실패가 반복 판정을 막지 않아야 한다. `processQueue()`도 실행 직전에 업로드 기간을 다시 검사하므로 큐 삽입 조건과 실행 직전 조건을 함께 수정해야 한다.

## 4. 상세 설계

### 4.1. 홈 방문 구분

- 최초 홈 진입, 브라우저 새로고침, 다른 페이지에서 홈으로 돌아오기, 로고 클릭으로 홈 피드가 새로 갱신되는 경우 새 방문 식별자를 부여한다.
- 스크롤, 주기 검사, DOM 교체, 팝업 설정 변경, 런타임 재생성은 기존 방문을 유지한다.
- `yt-navigate-start`, `yt-navigate-finish`, `popstate`가 한 탐색에서 중복 발생해도 방문은 한 번만 생성한다.
- 방문 상태와 방문 내 집계 상태는 필터 런타임보다 오래 유지한다. OFF 후 같은 페이지에서 다시 ON으로 바꿔도 이미 센 영상을 다시 세지 않는다.
- 탐색 시작 시 기존 감지와 대기 작업을 중단한다. 이전 방문의 지연 콜백·응답으로 새 페이지의 카드를 처리하지 않는다.

### 4.2. 실제 화면 노출 감지

- 홈 어댑터에서 `IntersectionObserver`와 문서 표시 상태를 이용해 노출을 판정한다.
- 숨겨진 다른 페이지의 DOM, 화면 밖 카드, 백그라운드 탭을 집계하지 않는다. 탭이 다시 보이면 현재 화면을 재평가하되 같은 방문 중복 규칙을 유지한다.
- 기존 영상 ID 추출을 재사용한다. 안정적인 ID가 없는 후보는 기록하거나 처리하지 않는다.
- 같은 영상의 중첩 DOM과 교체된 카드는 동일 ID로 집계한다. DOM이 다른 영상으로 재사용되면 새 ID를 재평가한다.
- 업로드 기간 검사로 `checked`가 된 카드도 반복 노출 감지를 받을 수 있어야 한다.
- 노출 감지 결과가 저장되기 전에는 추정 횟수로 반복 필터 작업을 실행하지 않는다.

### 4.3. 누적 기록과 중복 방지

프로필 공통 누적값과 탭별 중복 방지를 위해 다음 최소 정보를 관리한다.

| 데이터 | 용도 |
| --- | --- |
| 영상 ID별 누적 횟수 | 서로 다른 홈 방문에서 실제 노출된 횟수 |
| 방문 식별자와 해당 방문에서 집계한 영상 ID | `(visitId, videoId)` 단위 중복 방지 |
| 반복 필터 활성화 여부와 N | 팝업·콘텐츠 스크립트의 공통 설정 |

1. 콘텐츠 스크립트가 방문 식별자와 영상 ID로 노출 기록을 요청한다.
2. background가 유효한 방문인지 확인하고 같은 조합이 이미 기록됐는지 판단한다.
3. 처음 기록한 조합만 누적 횟수를 1 증가시킨다. 중복 요청에는 추가 증가 없이 저장된 결과를 반환한다.
4. 누적값과 중복 판정 기록을 함께 저장한 뒤 응답한다. 저장 후 응답 유실·재전송이나 워커 재시작에도 중복 증가하지 않도록 한다.
5. 콘텐츠 스크립트는 응답의 방문 식별자가 현재 방문과 일치할 때만 반복 필터 판정에 반영한다.

background를 단일 쓰기 경로로 두고 읽기→증가→저장을 직렬화한다. 여러 요청이 같은 이전 값을 읽어 증가분을 덮어쓰지 않아야 한다. 여러 탭 합산 시 영상별 `lastVisitId` 하나만 저장하는 방식은 사용하지 않는다. `A 방문 → B 방문 → A 재전송`도 중복 판정할 수 있어야 한다.

종료된 방문의 늦은 요청을 거부할 수 있게 한 뒤 해당 방문의 임시 중복 방지 정보만 정리한다. 영상별 누적값에는 TTL이나 오래된 항목 자동 삭제를 적용하지 않는다. 저장 용량 부족·저장 실패 시 기존 기록을 임의로 지우거나 저장되지 않은 횟수로 처리하지 않는다. 장기 용량 정책이 필요하면 누적 유지 요구와 함께 별도 결정한다.

### 4.4. 설정과 메시지 계약

- 반복 필터 활성화 여부와 N을 기존 `getState` 응답에 추가한다.
- 팝업의 설정 변경은 background에서 검증·저장한 뒤 기존 `applyFilter` 경로로 전달한다. 팝업과 background가 같은 설정을 중복 저장하지 않도록 한다.
- 방문 등록·종료와 노출 기록에 필요한 메시지는 `MESSAGE_PROTOCOL.md`에 요청, 응답, 중복 요청, 무효 방문, 저장 실패 동작을 기록한다.
- 전체 누적 이력을 매 카드 검사나 `getState`마다 전송하지 않는다. 현재 판정에 필요한 영상의 횟수만 반환한다.
- N 변경과 반복 토글 변경을 런타임에 반영하되 홈 방문 및 누적 이력은 유지한다.

### 4.5. 관심 없음 실행과 사유 표시

- 홈에서는 `기존 업로드 기간 조건 OR (반복 필터 ON AND 현재 방문에 실제 노출됨 AND 누적 횟수 >= N)`으로 판정한다.
- `/watch`는 기존 업로드 기간 필터를 유지하며 홈의 반복 노출을 집계하지 않는다.
- 큐 삽입과 실행 직전 모두 같은 판정 기준을 사용한다. 실행 직전 최신 설정, 현재 방문, 영상 ID와 카드 상태를 재검증한다.
- 반복 조건은 업로드 시점 파싱 여부에 의존하지 않는다. 두 조건을 만족한 영상도 기존 단일 큐에서 중복 요청하지 않는다.
- 반복 사유로 처리하면 `[홈에서 누적 3회 노출]`과 영상 제목을 표시한다. 두 조건 모두 해당할 때의 표시 기본안은 반복 사유 우선으로 둔다.
- 기존처럼 대상 카드의 YouTube 숨김 결과를 확인한 뒤에만 `Skipped`와 배지를 증가시킨다. 누적 노출 횟수와 `Detected`/`Skipped`는 별개다.
- 메뉴에 관심 없음이 없거나 결과 확인에 실패하면 기존 실패·재시도 정책을 따른다. 노출 누적값은 성공 여부와 무관하게 보존한다.

- [x] DOM이 다른 영상으로 재사용되면 새 영상을 구분한다.
- [x] 새로고침·홈 복귀·로고 갱신은 새 방문이며, 중복 탐색 이벤트와 설정 변경은 방문을 추가하지 않는다.
- [x] 워커 재시작·저장 후 응답 유실에도 누적값과 중복 판정이 유지된다.
- [x] 여러 탭 정책에 맞게 동시 요청을 처리하며 증가분 유실·중복 증가가 없다.
- [x] N을 낮추면 현재 방문에서 노출된 대상만 재평가하고, N을 높이면 새 기준을 실행 직전에 적용한다.
- [x] 기간 기준과 반복 기준을 모두 만족해도 같은 방문에서 요청·Skipped가 중복 증가하지 않는다.
- [x] 반복 필터 OFF, 전체/홈 OFF, 미로그인, 탐색 시작 시 해당 작업을 중단하고 누적값을 보존한다.
- [x] 숨김 결과 미확인 시 Skipped를 증가시키지 않고, 성공·실패 후에도 누적 노출을 초기화하지 않는다.
- [x] 저장 실패 시 미확정 횟수로 반복 필터를 실행하지 않는다.
- [ ] 실제 로그인한 YouTube의 한국어·영어 화면에서 기존 Watch 필터, 업로드 기간 설정, 로그인 안내, 숨김 사유와 Undo UI를 최종 확인한다. 자동 fixture 회귀는 통과했다.


실제 브라우저에서는 테스트용 YouTube 계정으로 한국어·영어 UI를 확인한다. 기준 시나리오가 날짜 필터에 먼저 처리되지 않도록 최근 영상을 사용하고, 새로고침·홈 복귀·스크롤·N 변경을 재현한다. 팝업과 숨김 사유 UI 변경은 화면을 기록한다.

성능 검증은 노출 없는 반복 스캔에서 저장 요청이 늘어나지 않는지, 영상당 방문 내 최초 노출만 저장하는지, 런타임 중단 시 observer가 해제되는지를 확인한다. 저장 메시지 수와 저장 데이터 크기를 측정하고 전체 이력의 반복 읽기·전송이 없는지 점검한다.
